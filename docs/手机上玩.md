# 在手机上玩《去屏東打怪》

有两条路。先看这张表选一条，再往下翻对应的章节，不用两条都读。

|  | **路线 A** 同一个 Wi-Fi 下玩 | **路线 B** 传到网上，装成 App |
|---|---|---|
| 第一次要花多久 | 约 1 分钟 | 约 15 分钟 |
| 玩的时候电脑要开着吗 | **要**，还不能睡着 | 不要，关机也行 |
| 能离线玩吗（飞行模式） | 不能 | **能** |
| 手机上有图标吗 | 没有（只能存书签） | **有**，和普通 App 一样 |
| 要注册账号吗 | 不要 | 要 GitHub（免费） |
| 代码会公开吗 | 不会 | 免费方案会公开 |

一句话：**想马上在手机上试一下 → 走 A；想真的当成一个 App 带出门 → 走 B。**

两条路互不影响，可以先 A 后 B。

---

## 路线 A：同一个 Wi-Fi 下直接玩

原理很简单：电脑变成一台小网站服务器，手机连同一个 Wi-Fi，输入电脑的地址就能打开。

### 1. 确认手机和电脑连的是同一个 Wi-Fi

同一个路由器、同一个名字的 Wi-Fi。手机开着 4G/5G 也没关系，但 **Wi-Fi 必须是同一个**。
（公司或学校的 Wi-Fi 有时会禁止设备之间互相访问，那种网络下这条路走不通，直接看路线 B。）

### 2. 电脑上开服务器

打开「终端」（按 `Command` + `空格`，输入「终端」回车），把下面两行粘进去，回车：

```bash
cd ~/Projects/crystal-quest
python3 tools/serve.py 8123 --lan
```

屏幕上会出现类似这样一段：

```
http://localhost:8123/  (调试 ?debug)  测试 /tests/

手机上打开（要和电脑连同一个 Wi-Fi）：

    http://192.168.31.129:8123/
```

**中间那个地址就是要在手机上输的。** 每个人的数字不一样，以自己屏幕上显示的为准。

> 第一次运行时，Mac 可能会弹窗问「是否允许 Python 接受传入网络连接」——
> 一定要点**允许**。点了「拒绝」手机就连不上，只能到「系统设置 → 网络 → 防火墙」里改回来。

`--lan` 这个开关是关键：不加它，服务器只允许电脑自己访问，手机连不上。

### 3. 手机上打开

手机浏览器的地址栏里，**一字不差**地输入上面那个地址，包括 `http://` 和最后的 `:8123`：

```
http://192.168.31.129:8123/
```

回车，游戏就出来了。

### 4. 玩完之后

回到终端，按 `Control` + `C` 停掉服务器。

之后只要**关掉终端、电脑睡着、或者手机换了 Wi-Fi**，手机上就打不开了——这条路本来就是「临时连一下」。

### 路线 A 为什么不能装到主屏幕

浏览器有一条安全规定：**「离线缓存」这个能力只在 `https://` 开头的网址、或者电脑自己的 `localhost` 上才允许开启。**
路线 A 的地址是 `http://192.168.x.x`，既不是 https，也不是 localhost，所以浏览器会拒绝。

这**不是游戏坏了**，是浏览器全球统一的规矩，任何网站都一样。

iPhone 上你仍然可以「添加到主屏幕」，但那个图标只是一个书签：
电脑一关就打不开，飞行模式下也打不开。想要真正装进手机、随时随地能玩，请走路线 B。

### 路线 A 打不开时

| 症状 | 多半是 |
|---|---|
| 手机一直转圈 / 说「无法连接」 | 忘了加 `--lan`；或者防火墙弹窗点了拒绝；或者两台设备不在同一个 Wi-Fi |
| 地址栏变成了搜索结果 | 少打了 `http://`，手机把它当成搜索词了 |
| 打开是一片空白 | 地址最后少了 `:8123` |
| 玩到一半突然断了 | 电脑睡着了。到「系统设置 → 锁屏」把自动睡眠关掉，或者在另一个终端窗口里跑 `caffeinate` |

## 路线 B：传到 GitHub Pages，装成手机 App

GitHub Pages 免费、自带 https、专门用来放这种没有后端的纯静态网页，是这个游戏最合适的去处。
传上去之后，游戏有一个固定网址，谁都能打开，手机上还能装成一个真正的 App 图标，断网也能玩。

### 开始之前

- 需要一个 GitHub 账号（[github.com](https://github.com) 免费注册）
- 电脑上要有 git。终端里输 `git --version`，能显示版本号就是有（Mac 一般自带）
- **注意：免费的 GitHub Pages 要求仓库是公开的（Public）**，也就是任何人都能看到这份代码和美术。
  如果不想公开，可以看本文最后的「不想公开代码的话」。

### 第 1 步：更新离线清单

```bash
cd ~/Projects/crystal-quest
python3 tools/gen_sw.py
```

会打印类似 `写好 sw.js：版本 5c005558a912，163 个文件，2.5 MB`。

**这一步以后每次更新游戏都要做，不能省。** 原因在最后一节「以后改了游戏怎么更新」里说。

### 第 2 步：把改动存进版本库

```bash
git add -A
git commit -m "可以装到手机上了"
```

### 第 3 步：在 GitHub 上建一个空仓库

1. 打开 [github.com](https://github.com)，右上角 **+** → **New repository**
2. **Repository name** 填 `crystal-quest`
3. 选 **Public**
4. 下面三个勾（Add a README / .gitignore / license）**都不要勾**——仓库必须是空的
5. 点 **Create repository**

### 第 4 步：推上去

建完仓库的页面上会显示你的仓库地址。回到终端（把 `你的用户名` 换成实际的）：

```bash
git remote add origin https://github.com/你的用户名/crystal-quest.git
git branch -M main
git push -u origin main
```

第一次推送会要求登录，浏览器会自动弹出 GitHub 的授权页面，按提示点同意即可。
（如果它问你要密码，别输 GitHub 的登录密码——那个已经不能用了。装个
[GitHub Desktop](https://desktop.github.com) 登录一次是最省事的办法，装完再回来跑这三行。）

整个仓库大约 7 MB，一两分钟能传完。

### 第 5 步：打开 Pages

1. 在仓库页面点 **Settings**（齿轮，在仓库名下面那一排的最右边）
2. 左边栏点 **Pages**
3. **Source** 选 `Deploy from a branch`
4. **Branch** 选 `main`，右边的文件夹选 **`/ (root)`**
5. 点 **Save**

> ⚠️ 文件夹一定要选 **`/ (root)`（根目录）**，不要选 `/docs`。
> `index.html` 就在仓库根目录，Pages 直接发根目录即可，不需要先打包。
> 那个 `/docs` 选项是给「网站放在 docs 文件夹里」的项目准备的；
> 我们的 `docs/` 里只有你正在读的这篇说明，选错了发出去的就是这篇文档。

### 第 6 步：拿到网址

等 1–3 分钟（第一次可能到 5 分钟），刷新 Settings → Pages 这个页面，顶上会出现绿色的网址：

```
https://你的用户名.github.io/crystal-quest/
```

在电脑上先打开确认能玩，再发到手机上（用微信/备忘录发给自己最方便）。

**第一次在手机上打开需要联网**，它要下载大约 2.5 MB 的图和字体存进手机。
之后就不需要网了。

## 装到手机主屏幕

**必须先完成路线 B**，拿到 `https://` 开头的网址。两个系统的步骤不一样。

### iPhone / iPad（用 Safari）

1. 用 **Safari** 打开那个 `https://...github.io/crystal-quest/` 网址
   （一定要 Safari，别用微信里点开的那个浏览器，也别用 Chrome）
2. 点屏幕**底部中间**的分享按钮（一个方框，里面一个向上的箭头 ⬆️）
3. 在弹出的菜单里往下划，找到 **「添加到主屏幕」**
4. 右上角点 **「添加」**

主屏幕上就会出现一个乌火的图标。点进去是全屏的，没有地址栏，和普通 App 一样。

> 如果菜单里找不到「添加到主屏幕」：往下划到底点「编辑操作」，把它打开。

### 安卓（用 Chrome）

1. 用 **Chrome** 打开那个网址
2. 通常屏幕下方会自己冒出一条 **「安装应用」** 的提示条，点它 → **安装**
3. 没冒出来的话：点右上角的 **⋮** → 菜单里选 **「安装应用」** 或 **「添加到主屏幕」** → **安装**

装好后图标会进应用抽屉，和别的 App 排在一起，可以拖到桌面。

### 装好之后可以验证一下

打开飞行模式，再点图标——游戏照常打开就说明离线缓存成功了。

## 需要知道的几件小事

### 存档存在手机本地

游戏的存档（菜单里的「记下 / 想起」）存在**当前这个浏览器、这个网址**里。所以：

- 路线 A 的存档和路线 B 的存档是**两份**，互相看不见
- 换一台手机、换一个浏览器，存档不会跟过去
- 清理浏览器数据会把存档一起清掉
- iPhone 上，**Safari 里玩的存档**和**主屏幕图标里玩的存档**很可能是分开的两份。
  建议装好图标之后，就一直从图标进去玩

### 中文字体和图标的路径问题（已经处理好了）

这一条是给以后自己改代码时看的，现在不用做任何事。

网址是 `https://你的用户名.github.io/crystal-quest/`——注意游戏并**不在网站根目录**，
而是在 `/crystal-quest/` 这个子目录下面。

所以代码里如果写了 `/assets/xxx` 这种**以斜杠开头**的路径，浏览器会跑去
`你的用户名.github.io/assets/xxx` 找文件，那里什么都没有，直接 404。

这个项目原本只有一处这样的写法：`index.html` 里加载中文像素字体的那两行
（`@font-face` 里的 `url("/assets/fonts/...")`）。它的症状很有迷惑性——
**游戏能跑、能走能打怪，但所有中文都变成豆腐块方框**，因为字体没下载下来。

现在已经改成相对路径 `./assets/fonts/...`，根目录部署和子目录部署都正确。
`manifest.webmanifest`、`sw.js`、图标的路径也全都是 `./` 开头的。

**以后自己加资源时记住一条：路径一律用 `./` 开头，不要用 `/` 开头。**
想检查有没有漏网的，在项目目录里跑：

```bash
grep -rn 'src="/\|href="/\|url("/' index.html src/
```

没有任何输出就是干净的。

### .gitignore 会不会把游戏要用的文件漏掉

不会，已经逐个查过了。`.gitignore` 目前排掉的是：

```
.DS_Store   node_modules/   *.log   .gemini_key
assets/art/raw/   dist/   tools/_cap/
```

其中和资源有关的只有两个，都是该排的：

- `assets/art/raw/` —— Gemini 出的原始大图（3.6 MB），只有 `tools/` 里的美术脚本
  拿它重新加工，游戏运行时**从来不加载**它
- `dist/` —— `tools/build.py` 生成的打包目录，里面全是从别处复制过去的副本

游戏真正需要的东西：`index.html`、`src/`、`data/`、`assets/art/*.png`、
`assets/fonts/*.woff2`、`assets/icon-192.png`、`assets/icon-512.png`、
`manifest.webmanifest`、`sw.js` —— **一个都没有被排掉**，全部会正常推上去。

想自己确认某个文件会不会被漏掉：

```bash
git check-ignore -v 文件名     # 没有输出 = 不会被漏掉
```

### 以后改了游戏怎么更新

```bash
cd ~/Projects/crystal-quest
python3 tools/gen_sw.py                  # ← 这一步不能省
git add -A
git commit -m "改了点东西"
git push
```

等 1–2 分钟，手机上把游戏**从后台完全划掉**再点图标进去，就会自动更新。

**为什么 `gen_sw.py` 不能省：** 装到手机上之后，游戏是「先读手机里的缓存」再考虑联网的
（这样才能离线玩）。`sw.js` 里存着一份文件清单和一个版本号，手机靠**版本号变了没有**
来判断要不要重新下载。不重新生成 `sw.js`，版本号就不变，手机会一直认为「我这份是最新的」，
你推上去的新内容它永远看不到。

（换了图标的话，还要先跑一次 `python3 tools/gen_icons.py` 重新合成图标，再跑 `gen_sw.py`。）

### 不想公开代码的话

免费的 GitHub Pages 只能发公开仓库。想让代码保持私有，有两个替代：

- **Cloudflare Pages** 或 **Netlify**：注册后在网页上把项目文件夹**直接拖进去**就发布了，
  同样免费、同样有 https，不需要仓库公开，也不需要用 git。
  拖之前先跑一次 `python3 tools/build.py`，然后拖 `dist/` 文件夹（那里面是挑干净的运行时文件）。
  唯一的差别是每次更新都要重新拖一次。
- **GitHub Pro**（付费）：私有仓库也能开 Pages，步骤和上面完全一样。

### 路线 B 出问题时

| 症状 | 多半是 |
|---|---|
| 打开是 404 页面 | Pages 还没生成好，再等两分钟刷新；或者第 5 步的文件夹选成了 `/docs` |
| 中文全是方框 ▯▯▯ | 字体路径又变回 `/assets/` 了，见上面「路径问题」那节 |
| 能玩，但没有「安装应用」的提示 | 网址不是 `https://` 开头；或者用的不是 Chrome/Safari |
| 改了代码推上去，手机上还是旧的 | 忘了跑 `python3 tools/gen_sw.py`，或者没把 App 从后台划掉重开 |
| 电脑上想测离线／主屏幕 | 地址后面加 `?pwa`，例如 `http://localhost:8123/?pwa` |
| 改了代码但页面没变 | 本机开发时**不会**注册离线缓存（见下），所以正常刷新就够；若你加过 `?pwa`，去掉它再刷新 |


## 为什么本机开发时离线缓存是关掉的

离线缓存（service worker）是 **cache-first** 的：一旦装上，浏览器就优先发缓存里那份，
**改了源码刷新页面也纹丝不动**。这一条踩过——改完标题页的操作提示，页面上还是旧文案，
查了半天才发现是缓存在发旧文件。

所以 `src/pwa.js` 做了个判断：地址是 `localhost` / `127.0.0.1` 时**不注册**，
而且会把之前装上的**主动注销、清掉缓存**。要在电脑上专门验证离线与主屏幕效果，
地址后面加 `?pwa` 即可。

部署到 GitHub Pages / Cloudflare Pages 之后不受这条影响，玩家那边照常有离线缓存。
但记住：**每次更新内容都要先跑一次 `python3 tools/gen_sw.py`**，
缓存认的是版本号，不重跑手机上永远是旧的。
