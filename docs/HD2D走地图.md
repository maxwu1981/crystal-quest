# 走地图那半的 HD-2D：方案与实测

2026-09-07。战斗那半已经做过一轮（透视斜面、落影、景深、尺寸随深度、Gemini 天空）。
这份文档只管**走地图**：内埔庄、六堆平原、罗经圈两层、隘寮石城、万金古塚。

先把 `docs/HD2D评估.md` 那句结论抄在最上面，因为下面每一条的排序都是从它推出来的：

> 看不出歧路旅人是因为**画面里没有光、人没有影、也没有一个统一的镜头**——
> 这三样都是二三十行代码，而力气花在了压色数上，那恰恰是唯一测不出观感变化的一项。

## 零、先看现状：走地图现在到底缺什么

六张图各渲一帧回读（`tools/_cap/B_*.png`，看完删）。逐张记下来的：

| 图 | 现状 | 最刺眼的一条 |
|---|---|---|
| 内埔庄 | 屋顶/墙有手画的明暗序，地上有**手摆的**影格（`shadow_dirt`/`shadow_grass`） | 影子**只在房子正下方一格**，房子右侧一点影都没有；草地在尖叫 |
| 六堆平原 | 山、林、草各自成片 | 山脚下的草是**全亮的**——一座山压在草地上却不投影 |
| 罗经圈外围/深处 | 有暗角（`vig`），靠主角照明 | 岩壁与地面**同一个亮度分布**，墙不像墙，像地面换了个花纹 |
| 隘寮石城 | 有 22% 的暖色调层 | 八根柱子、四面墙、两座台——**没有一片影子**，整张图是印在纸上的 |
| 万金古塚 | 最暗的一张 | 同上，且走廊两侧的墙没有任何受光边 |

三句话总结：

1. **光**：只有 `ambience.js` 一层**全屏乘法色调**（`tint`/`tintA`）+ 一个跟着主角走的暗角。
   没有方向。`src/assets/terrain.js` 的 `shadowTile` 压暗 N/W/NW 三个方向（说明**光向已经定死是左上**），
   但**没有对称的受光边**——有影无光，等于只做了减法。
2. **影**：`npc.js` 的 `drawShadow` 只有主角/NPC，树和宝箱各自在瓦片里烘了一小片。
   **墙、柱、建筑、山这些有体积的东西，一片投影都没有。**
   现有的崖影只有 `u(1)×5 = 5 逻辑像素`高——那是接触影（AO），不是太阳影。
3. **镜头**：战斗是压低的斜视（`perspRows`/`converge` 画出了灭点），走地图是正俯视。
   **同一个世界两套镜头**，切过去一眼就穿帮。

## 一、四件事的优先级与依据

排序依据只有一条：**「一眼能不能看出来」÷「改动量 × 风险」**。

### 第 1 位 — 光与影（合成一件事做）

**依据**：评估文档把「没有光、没有影」排在前两位，而这两样在走地图这边是**同一个缺口的两面**——
`terrain.js` 已经把光向定死在左上（`shadowTile` 只认 N/W/NW），缺的是
① 对称的受光边、② 长度像样的投影、③ 墙体的立面暗部。
三样共用同一个光向、同一次遍历、同一张贴图，**做一件事拿三样**，所以排第一。

不做的话，后面三件都是在一张平的图上加特效。

### 第 2 位 — 镜头（纵向光度渐变 + 移轴景深）

**依据**：这是唯一一件能让「走地图」和「战斗」看起来是同一台摄影机拍的。
而且它是**屏幕空间**的，跟地图内容完全无关：改坏了删两行就回滚，不可能弄脏任何一张瓦片。
排第二而不是第一，是因为在一张没有光影的平图上做移轴，糊掉的还是那张平图（这一点和
`docs/HD2D方案.md` 阶段 0 把景深往后放是同一个理由）。

### 第 3 位 — 落影升级与粒子景深

**依据**：现在的落影是 `alpha 0.22` 的**居中**椭圆——它是「贴纸的锚点」，不是「光压出来的影」。
改成朝光向偏移、拉长、并给站着的物件（柱/箱/树）也补一片，是十几行。
粒子景深（`par` 小的更淡更糊）是 `docs/HD2D方案.md` 第二节⑧记的零成本项，顺手做掉。

### 第 4 位 — 高处物件的 y 位移（评估后**决定不做**，见第五节）

## 二、逐条设计

### 2.1 光照贴图 `src/field/lightmap.js`（新档）

**为什么不改 `src/assets/terrain.js` / `terrainBake.js`**（`docs/HD2D方案.md` 阶段 0-3 原本是这么写的）：
`src/assets/**` 这一轮被另一位占着（在重出瓦片、改 `art.js`/`tiles.js`），碰不得。
换个地方做反而更好：光照是**地图级**的东西（一堵墙的影子要跨好几格），
而 `terrainBake.js` 那套是**一格一张缓存图**，跨格的长影子在那个模型里根本表达不出来
（现在的崖影只有 5 逻辑像素高，正是被这条边界卡住的）。

**做法：整张地图烘一张「光照贴图」，每帧一次 `drawImage`。**

- 分辨率 **1 贴图像素 = 1 逻辑像素**（`map.w*16 × map.h*16`）。最大的六堆平原 640×512 = 1.25 MB，
  内埔庄 1.20 MB，其余都在 0.7 MB 以下。渲染时被 ART=6 的变换放大 6 倍并开插值，
  于是**放大本身就是柔化**——影子的半影是免费的。
- 两张贴图，两种合成：
  - **阴影贴图**：不透明白底（白 = 不压暗），用 `darken` 画灰。渲染时 `multiply`。
  - **受光贴图**：不透明黑底（黑 = 不加亮），用 `lighten` 画光色。渲染时 `lighter`。

  两种合成模式**这个项目都已经在用**（`FieldScene` 的崖影层用 `multiply`，宝箱微光用 `lighter`），
  不引入没验证过的 `overlay` / `soft-light`——那两个万一在某个浏览器上退化成 `source-over`，
  会把整张贴图**盖在画面上**，是灾难性失败而不是降级。

**`darken` / `lighten` 在不透明画布上就是逐通道 min / max**，这一点是整套烘焙的地基：
同一堵墙的投影要画成七片依次偏移的方块，`source-over` 会让它们互相叠加成一团黑，
而 `darken` 取最暗的那一片＝最近的那一片，得到的正好是单调递减的拖影。

**四样东西画在这两张贴图上：**

1. **长投影**。光向沿用 `tiles.js`/`terrain.js` 的约定（左上来光），影子朝右下拖：
   `SUN = { dx: 0.55, dy: 1.0, len: 11 }`——一格高的东西拖 11 逻辑像素（约 0.7 格）。
   长度按物件高度缩放（`TALL` 表：整墙 1.0、屋脊 1.25、树 0.75、柱 0.8、木箱 0.4、床 0.25）。
2. **投影不落在墙上**。画完之后用 `lighten` 把所有「高物」格子擦回白色——
   否则村庄的屋脊会把影子投在自家屋顶上。村庄那 46 格**手画的影格**
   （`shadow_dirt`/`shadow_grass`）擦掉七成：那里本来就是影子，再乘一次会糊成一团黑，
   但留三成让新的软影**接着它往下化开**（现在那条边是硬的）。
3. **立面暗部**。高物格子的下缘 5 逻辑像素压一道由浅入深的暗带——
   墙就从「一块顶面」变成「一块顶面 + 一道转折」。这是导演说的「画出正面」里
   **唯一不动地图数据、不吃掉可走地面**的那半（另一半为什么不做见第五节）。
   它画在模糊之后，所以那道转折是硬的（立面的转折本来就该是硬的），而投影是软的。
4. **受光棱**。高物格子朝北（顶）的那条边描 3 像素亮线，朝西（左）的描 2 像素、亮度减半——
   `terrain.js` 只做了减法（崖影），这是补上的那一半加法。

**烘焙顺序**（顺序本身是设计的一部分）：
`投影 → 擦掉高物 → 降采样 1/3 再放大回来（软化）→ 立面暗部（硬）`。
模糊那一步用降采样，**不用 `ctx.filter='blur'`**——`docs/HD2D方案.md` 第五节第 3 条实测
小半径反而比大半径贵好几倍。而且这里是**烘焙期**跑一次，逐帧零成本。

**跳过被包住的墙**：四周（右/下/右下）都是高物的格子，它的影子会被第 2 步全擦掉，
直接不画。罗经圈那种整片岩壁的图，这一条把要画的格子砍掉七成。

**缓存**：按地图 id 存，只留最近 3 张（约 2~4 MB）。手机上不留 18 张。

**防闪**：整张贴图与时间**完全无关**，逐帧只是 `drawImage` 同一张图。**不可能闪。**

### 2.2 镜头 `src/field/postfx.js`（新档）

两件事，都在屏幕空间：

**（a）纵向光度渐变（空气透视）。** 一次带线性渐变的 `fillRect`（`multiply`）：
上缘偏冷偏暗（`rgba(150,168,196,0.30)`）→ 42% 处透明 → 下缘微暖（`rgba(255,236,206,0.14)`）。
俯视图里「上＝远」，远处压暗降饱和、近处提暖，是压低机位最便宜的读法。
战斗那边 `perspRows` 是把地面画成斜面，这边没有斜面可画，但**明度梯度是同一句话**。

**（b）移轴景深。** 整幅画降采样到 1/4 离屏，再把上 19% / 下 12% 两条带放大回来。
每条带切三小条、`globalAlpha` 依次 1.0 / 0.62 / 0.28 —— 相当于「清晰版」与「模糊版」
在内缘做交叉淡入，边界不会切出一条线。

**三条硬约束：**
- **必须画在 UI 之前**：地图名条、小地图、摊开的全图、对话框都在 `FieldScene.render` 最后几行。
  糊掉文字就是 bug。
- **不能糊到主角**：主角永远在镜头中心附近，两条带各自离屏幕中线还有 60+ 逻辑像素。
  室内小图（`mh <= H`，地图比屏幕矮）**整个关掉**——那种图主角可能站在任何高度。
- `game.state.settings.dof === false` 时关掉，给设置菜单留口（菜单在 `src/menu/`，这一轮不碰）。

**防闪**：同样与时间无关。

### 2.3 落影与粒子 `src/field/npc.js` / `src/field/ambience.js`

- `drawShadow` 加两个可选参数（高度、宽度系数），椭圆中心朝光向偏 1.5 逻辑像素、
  长轴拉到 0.34 格、加一圈更淡的外晕（两次 `ellipse`，第二次 alpha 减半、半径 ×1.35）。
  两个参数都有默认值，**所有既有调用点一个字不用改**。
- 粒子景深：`par`（视差）小的＝远的，透明度乘 `0.45 + 0.55*par`，并且远的画 2×1 而不是 1×1。
  `makeMotes` 已经有 `par` 字段，只是没人用它调亮度（`docs/HD2D方案.md` 第二节⑧记着这条）。

### 2.4 MOOD 补齐

`village` / `overworld` 是**唯二**没有 `vig` 的图，于是它们四个角是齐亮的，
读起来像一张摊平的贴图。补一层极浅的暗角（`a: 0.16~0.18`，比洞窟浅一半以上）。
另外给每张图加一个可选的 `sun: { a, lit, face, col }`，让光照贴图按场景调
（正午的村庄影子最实、洞窟里影子还在但受光棱偏冷偏弱）。
